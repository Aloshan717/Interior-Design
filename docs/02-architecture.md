# ٢ — المعمارية

## المبدأ الحاكم

> كل شيء يمكن أن يتغيّر لاحقاً — مزوّد الـAI، مصدر المنتجات، مكان التخزين، بل الواجهة نفسها — يقف خلف **واجهة مجرّدة**. الشاشات لا تعرف من يولّد الصور ولا من أين تأتي الأسعار.

هذا تنفيذ مباشر للبندين ٢٨ و٢٩.

## لماذا تطبيق ويب PWA؟

| | السبب |
|---|---|
| لا يحتاج Mac ولا Xcode ولا $99 | القرار المعتمد: لا شراء Mac |

## الـStack

| الطبقة | التقنية | لماذا |
|---|---|---|
| الواجهة | React 18 + Vite | سريع، ومألوف لك من GAUGE |
| التوجيه | موجّه داخلي بسيط | ٣ تبويبات فقط — لا داعي لمكتبة |
| التنسيق | CSS Variables + Modules | تحكم كامل بالإحساس الفاخر، صفر تبعيات |
| الحالة | React Context + Reducer | كافٍ تماماً لهذا الحجم |
| التخزين | IndexedDB أولاً + Supabase اختياري | الصور ثقيلة — المحلي أسرع وأرخص |
| الخادم | دوال Vercel | مكان المفاتيح |
| الصور | fal.ai · Flux Kontext | الحفاظ على هندسة الغرفة + تعديل موضعي |

**قرار: لماذا IndexedDB أولاً وليس Supabase؟**
صور غرفتك بحجم ٢–٥ ميجابايت للصورة. رفعها كلها للسحابة يبطئ التجربة ويستهلك حصتك بلا فائدة — أنت المستخدم الوحيد على جهاز واحد. Supabase يبقى **اختيارياً** للمزامنة بين أجهزتك، خلف نفس الواجهة (`StorageService`) فلا تتأثر أي شاشة.

## مكونات الذكاء الاصطناعي

أربع مهام منفصلة، كل واحدة قابلة لتبديل مزوّدها استقلالاً (البند ٢٩):

| # | المهمة | المدخل | المخرج | النموذج |
|---|---|---|---|---|
| ١ | **تحليل المكان** | صور الغرفة | وصف نصي منظّم: الأبعاد التقريبية، النوافذ، الأبواب، الأرضية، الإضاءة، الأثاث الحالي | نموذج رؤية |
| ٢ | **بناء الملف الذوقي** | الصور المرجعية المختارة | ملف ذوق: ألوان، خامات، مستوى فخامة، إضاءة + جملة عربية مبسّطة | نموذج نصي |
| ٣ | **توليد التصميم** | صورة الغرفة + الملف الذوقي + التصور + القيود | صورة التصميم | Flux Kontext |
| ٤ | **فهم أمر التعديل** | نص المستخدم + حالة التصميم | نيّة منظّمة: `{نوع، عنصر مستهدف، تغيير}` | نموذج نصي |

### الواجهة المجردة

```js
// كل مزوّد ينفّذ هذه الواجهة — لا أكثر
export const AIProvider = {
  analyzeSpace({ images, roomType, notes }),        // ← ١
  buildStyleProfile({ selectedRefs }),              // ← ٢
  generateConcepts({ spaceAnalysis, styleProfile, count }),
  generateRoomDesign({ roomImage, spaceAnalysis, styleProfile, concept, constraints }), // ← ٣
  parseEditIntent({ text, currentDesign }),         // ← ٤
  applyEdit({ baseImage, intent, preserveMask }),
};
```

**المزوّدون:**
- `MockProvider` — يعمل الآن بلا مفاتيح ولا تكلفة. يحاكي التأخير والنتائج لتجربة الرحلة كاملة.
- `FalKontextProvider` — يُفعّل بمتغير بيئة واحد عند جاهزية المفاتيح.

**تبديل المزوّد:** سطر واحد في `lib/ai/index.js`. لا شاشة تتغير.

## معالجة الانتظار الطويل

توليد الصورة يستغرق ٢٠–٦٠ ثانية، و٤ تصورات على التوازي قد تصل لدقيقة ونصف. الطلب المباشر الذي ينتظر النتيجة يفشل (المتصفح والخادم كلاهما يقطعان الاتصال).

**النمط المعتمد — مهمة في الخلفية:**

```
التطبيق → POST /api/generate           → يعيد jobId فوراً
التطبيق → GET  /api/job/:id  (كل ٢ ثانية) → pending → done + الصورة
```

فوائده: لا انقطاع، ولو أغلق المستخدم الشاشة تستمر المهمة، وشريط التقدم يعكس **مراحل حقيقية** لا مؤقتاً وهمياً (البند ٢٤).

**عرض تدريجي:** التصورات الأربعة تظهر كل واحد فور جاهزيته، لا انتظار الأربعة معاً.

## حدود الـAPI

| المسار | الطريقة | المدخل | المخرج |
|---|---|---|---|
| `/api/analyze-space` | POST | صور (base64) + نوع الغرفة | تحليل منظّم |
| `/api/style-profile` | POST | معرّفات الصور المختارة | ملف ذوق |
| `/api/generate` | POST | نوع المهمة + السياق | `{ jobId }` |
| `/api/job/:id` | GET | — | `{ status, progress, result }` |
| `/api/edit` | POST | صورة الأساس + نص التعديل | `{ jobId }` |
| `/api/products/match` | POST | عناصر التصميم + الميزانية | قائمة منتجات |

**عقد ثابت:** أي مزوّد جديد يجب أن يلتزم بنفس شكل المدخل والمخرج. المزوّد يتغيّر — العقد لا.

## الأمان

| القاعدة | التنفيذ |
|---|---|
| لا مفتاح في المتصفح | كلها في متغيرات بيئة Vercel |
| كل استدعاء خارجي عبر `/api` | لا `fetch` مباشر من الشاشات |
| صور الغرفة | تبقى على جهازك، تُرسل للتوليد فقط عند الحاجة |
| حد استهلاك | سقف يومي للطلبات في دوال الخادم — يحميك من خطأ برمجي يستنزف الرصيد |
